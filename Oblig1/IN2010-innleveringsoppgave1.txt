        gjorde ganske store endringer da jeg så at midten flyttet seg mens man la til noder i lista
        måtte ta hensyn til når man la i en liste som hadde færre enn tre elementer
        lagde også lista dobbellenket slik at jeg kan finne elementet før og etter midten raskt
        sjekket hver gang middle ble oppdatert om den måtte flyttes, dette utifra hvor manlegger til og 
        om størrelsen på lista er partall eller oddetall. ved partall skal jo det nye elementet legges faktisk
        i midten, og ved oddetall skal elementet ligge på siste av de to midterte
        */

        procedure push_front
            ny <- new Node(x)
            if start = null then
                start <- ny
                middle <- ny
                end <- ny
            ny.next = start
            start.next = ny
            size ++

        procedure push_back
            ny <- new Node(x)
            if start = null then
                start <- ny
                middle <- ny
                end <- ny
            end.next = ny
            end = ny
            size ++

        procedure push_middle
            kopi <- middle.next
            if start = null then
                start <- ny
                middle <- ny
                end <- ny
            middle.next = ny
            ny.next = kopi
            size ++

        procedure get(i)
            if i = 0 then
                return start
            tmp <- start
            a <- 0
            while a < i do
                tmp = tmp.next
                a++
            return tmp


    b) filnavn: Teque.java


    c) Verste tilfelle av kjøretidsanalyse (uten begrensning av N):
        push_back(x), push_front(x), push_middle(x):
            konstanttid: O(1)
        fordi: operasjonene kaller på noder med pekere på seg og trenger derfor ikke gå gjennom lista

        get(x):
            lineærtid: O(n)
        fordi: hvis get metoden kaller på noe annet enn det første eller siste elementet, går metoden gjennom (nesten) hele lista til den finner elementet



    d) Hvorfor størrelsen på N påvirker kjøretiden:
        push_back(x), push_front(x), push_middle(x):
            Operasjonene vil gå i konstanttid fordi det finnes peker til første, midterste og siste node. 
            Derfor vil ikke operasjonene påvirkes av størrelsen på N (input) og derfor heller ikke lengden av køen (teque).

        get(x):
            Dersom det ikke er første eller siste node som skal hentes, vil kjøretiden økes lineært med input sin størrelse (N)
            Dette er fordi metoden ble laget slik at den må lete gjennom alt i lista før den noden x man leter etter.
            I verste tilfelle må get-metoden derfor lete gjennom hele lista (bortsett fra helt siste node)
